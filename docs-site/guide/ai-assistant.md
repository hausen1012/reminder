# AI 助手

AI 助手让你用自然语言创建通知通道与提醒，不用一格格填表单：

> 「每天早上 9 点提醒我喝水，发到钉钉」
>
> 「帮我建一个邮件通知渠道，发件人用 noreply@example.com」
>
> 「把标题是『交房租』的提醒改成每月 1 号上午 10 点」

助手会调用系统内的工具查通道、查提醒，并把「要执行的写操作」做成**待确认卡片**，
你点「确认」后才真正写库。这是刻意的设计：模型误解意图时不会静默改动数据。

## 入口

登录后，面板**右下角**有一个悬浮的 ✨ 按钮，点开就是对话窗（桌面端浮在右下角，
移动端接近全屏）。它不占侧边栏导航，也不打断你正在做的事——
你可以在提醒列表页直接说「把这条改成每月 1 号」。

按钮上的红色角标是**待确认操作的数量**，即使你关掉浮窗也会显示。

::: tip 对话不保存
聊天记录**不入库**，只存在当前浏览器标签页的 `sessionStorage` 里：刷新页面还能接着聊，
关掉标签页就清空。这样做是因为回看旧对话的价值远低于它带来的数据库膨胀与隐私暴露。

真正落库的只有两样：**待确认草稿**（刷新后仍在，确认后才生效）与**加密后的 API Key**。
:::

## 开启

1. 打开面板**设置 → AI 助手**；
2. 选择厂商协议、填写模型名与 API Key；
3. 点「测试连接」确认可用，再打开「启用 AI 助手」并保存。

需要的话可以再填一段[自定义提示词](#自定义提示词)，微调助手的称呼与回复风格。

侧边栏就会出现**AI 助手**入口。

## 支持的厂商

| 协议 | 适用 |
|---|---|
| `anthropic` | Anthropic 官方 API，以及任何实现了 Anthropic Messages 协议的中转站 |
| `openai` | OpenAI Chat Completions 协议：OpenAI、DeepSeek、Moonshot、通义、Ollama、vLLM 等 |

两者的区别只在请求格式，功能（工具调用、多轮对话、待确认卡片）完全一致。

**Base URL**：

- Anthropic 留空使用官方地址，填中转站地址则走中转；
- OpenAI 兼容协议留空时默认 `https://api.openai.com`，其余厂商需要填写，例如：
  - DeepSeek：`https://api.deepseek.com`
  - Moonshot：`https://api.moonshot.cn`
  - 本地 Ollama：`http://localhost:11434`

系统会自动补上 `/v1` 前缀，填域名或填到 `/v1` 都可以。

**API Key**：加密后保存在数据库里（与通道敏感字段同一套 `ENCRYPTION_KEY`）。
设置页读回时显示为 `***`，不动输入框就表示不修改。本地 Ollama、vLLM 这类无需鉴权的服务可以留空。

::: tip 常用厂商预设
设置页的「快速填充」可以一键填入 DeepSeek / Moonshot / Ollama 等的默认地址与模型名，填完仍可改。
:::

## 自定义提示词

除了内置的系统提示词（站点时区、时间格式、工具使用与「待确认后才生效」等规则），
设置页的「自定义提示词」可以让你再追加一段自己的要求，两者拼接后一起发给模型。

它适合放**风格与业务约定**这类只有你知道的偏好，例如：

- 「称呼我为『老板』，回复尽量一句话说完」；
- 「提醒标题统一加上『⏰』前缀」；
- 「我提到『体检』时，默认提前一天再提醒一次」。

追加内容始终排在**内置规则之后**，并且明确要求模型两者冲突时以内置规则为准——
待确认机制、时间格式、先查通道再建提醒这些硬性约束不会被自定义内容绕过。
最多 4000 字，留空表示只用内置提示词。

::: warning 提示词会随每轮工具调用重复发送
单次对话最多 8 轮工具调用，每一轮都会带上完整的系统提示词。
写得很长的自定义内容会明显抬高 token 消耗，够用就好。
:::

## 助手能做什么

| 工具 | 作用 | 是否直接生效 |
|---|---|---|
| `list_channels` | 列出已配置的通道 | 只读 |
| `list_reminders` | 列出已有提醒（最多 20 条） | 只读 |
| `create_channel` | 新建通知通道 | **需确认** |
| `create_reminder` | 新建提醒 | **需确认** |
| `update_reminder` | 修改提醒 | **需确认** |
| `delete_reminder` | 删除提醒 | **需确认** |

创建提醒时助手必须先查通道拿真实 id，不会凭空编造；系统里一条通道都没有时，
它会先提示你建通道。删除提醒前它也会先查一遍，避免删错。

## 待确认卡片

每条写操作都会在对话里生成一张卡片，标注操作类型、摘要与当前状态。
卡片是**跨刷新、跨设备**的：关掉浮窗、刷新页面、甚至换一台设备打开面板，
待确认的操作都还在——打开浮窗时按「待确认」状态重新拉取。

草稿没有「属于哪次对话」的概念：它就是一个全局的待办队列，谁确认就算谁的。

| 状态 | 含义 |
|---|---|
| 待确认 | 还没执行，可以「确认」或「忽略」 |
| 已执行 | 已写入数据库，`result_ref` 记录了目标对象；卡片从列表移除 |
| 已拒绝 | 你点了忽略，不会再执行；卡片从列表移除 |
| 执行失败 | 执行时报错（如名称冲突），`error` 字段记录原因 |

已处理的操作不能重复执行，重复请求会返回 `conflict`，避免重复创建。

AI 创建的提醒的来源字段是 `ai`：提醒列表、日志列表都会显示紫色的「AI」标签，
也可以按来源筛选。它的每次触发日志同样标为 `AI`，方便事后区分哪些提醒是助手替你建的。

## 安全与边界

- **AI Key 与草稿内容都加密入库**：草稿里可能包含你口述的 SMTP 密码，落库前先加密。
- **不绕过校验**：草稿执行时走的是和表单完全相同的服务层校验，非法数据在执行阶段会被拒绝。
- **工具调用有上限**：单次对话最多 8 轮工具调用，模型陷入循环时请求也会结束。
- **历史回灌有上限**：客户端上传的历史最多 30 条，超出部分服务端丢弃。
- **对话不保留上下文跨标签页**：服务端无状态，上下文完全由浏览器提供；关掉标签页即从零开始。

::: warning 模型仍可能理解错
确认卡片是最后一道防线，但请养成看一眼卡片摘要再点确认的习惯——
尤其是删除操作。摘要里会带上目标标题，与你的意图不一致就别点。
:::

## 草稿的自动清理

待确认草稿与已处理草稿都**保留 90 天**，每天凌晨 3 点自动清理一次，
无需配置、也没有开关：

- 保留期按草稿的**创建时间**算，不是确认时间；
- 待确认（pending）也会被清理——放了 90 天没人点的草稿，对应的提醒或通道多半已经变了，
  留着只会让浮窗角标永远挂着数字；
- 清理只删 `ai_actions` 这一张表，不会影响任何真实存在的提醒或通道。

这条清理任务和日志清理一样挂在调度器上，改站点时区后会自动恢复，不会丢。

## 关于历史

浮窗右上角的垃圾桶图标可以清空当前对话（连同本地存储）。

清空对话**不会**撤销已经执行过的提醒和通道——它们在提醒页、通知页里独立存在；
也不会撤销待确认的草稿，那些仍会出现在卡片区。
