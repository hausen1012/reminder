# AI 助手

AI 助手让你用自然语言创建通知通道与提醒：

> 「每天早上 9 点提醒我喝水，发到钉钉」
>
> 「把标题是『交房租』的提醒改成每月 1 号上午 10 点」

助手会调用系统内的工具查通道、查提醒，并把写操作做成**待确认卡片**，点「确认」后才写库。

## 入口

登录后面板**右下角**有一个悬浮按钮，点开即对话窗（移动端接近全屏），不打断当前页面。
按钮角标是待确认操作数量。

聊天记录**不入库**，只存在当前标签页的 `sessionStorage`，关掉标签页即清空。
落库的只有待确认草稿与加密后的 API Key。

## 开启

1. 打开**设置 → AI 助手**；
2. 选择厂商协议、填写模型名与 API Key；
3. 点「测试连接」确认可用，打开「启用 AI 助手」并保存。

## 支持的厂商

| 协议 | 适用 |
|---|---|
| `anthropic` | Anthropic 官方 API，以及实现了 Anthropic Messages 协议的中转站 |
| `openai` | OpenAI Chat Completions 协议：OpenAI、DeepSeek、Moonshot、通义、Ollama、vLLM 等 |

两者只是请求格式不同，工具调用、多轮对话、待确认卡片的行为一致。

**Base URL**：Anthropic 留空走官方地址；OpenAI 兼容协议留空默认 `https://api.openai.com`，
其余厂商需要填写，例如 DeepSeek `https://api.deepseek.com`、Moonshot `https://api.moonshot.cn`、
本地 Ollama `http://localhost:11434`。系统会自动补 `/v1` 前缀，填域名或填到 `/v1` 都可以。

**API Key** 加密保存（与通道敏感字段同一把 `ENCRYPTION_KEY`），读回时显示为 `***`，
不动输入框即不修改。Ollama、vLLM 这类无需鉴权的服务可以留空。

设置页的「快速填充」可以一键填入常用厂商的默认地址与模型名。

## 切换模型

对话窗输入框右下角、发送按钮左侧有模型下拉框，选项来自设置页的模型列表。

切换只对本次会话生效：选中的模型随每次请求放在 `model` 字段里发送，不写回设置。

## 自定义提示词

设置页的「自定义提示词」会追加在内置系统提示词之后，适合放称呼、回复风格、业务约定等偏好，
例如「称呼我为『老板』」「提醒标题统一加前缀」。

追加内容不能绕过内置规则（待确认机制、时间格式、先查通道再建提醒），最多 4000 字，留空表示只用内置提示词。
提示词会随每轮工具调用重复发送，写太长会明显增加 token 消耗。

## 可用的工具

| 工具 | 作用 | 是否直接生效 |
|---|---|---|
| `list_channels` | 列出已配置的通道 | 只读 |
| `list_reminders` | 列出已有提醒（最多 20 条） | 只读 |
| `create_channel` | 新建通知通道 | 需确认 |
| `create_reminder` | 新建提醒 | 需确认 |
| `update_reminder` | 修改提醒 | 需确认 |
| `delete_reminder` | 删除提醒 | 需确认 |

创建提醒时助手会先查通道拿真实 id；系统里没有通道时会先提示建通道。删除前也会先查一遍。

确认提醒也可以对话创建：「这个提醒需要确认，重试 3 次，间隔 60 秒」会把
`require_confirm`、`confirm_retry_interval_sec`、`confirm_max_retries` 一起写进草稿，
效果与表单勾选「需要确认」相同，机制见[确认机制](/guide/confirmation)。

只说了「需要确认」而没给数值时，按表单默认值补齐：间隔 300 秒、重发 3 次；
低于下限（间隔 60 秒、次数 1）同样按默认值补齐。

AI 创建的提醒来源为 `ai`，提醒列表、日志列表都会显示紫色「AI」标签，也可以按来源筛选。

## 待确认卡片

每条写操作生成一张卡片，标注操作类型、摘要与状态。草稿跨刷新、跨设备存在，
打开浮窗时按「待确认」状态重新拉取；它是个全局待办队列，不区分属于哪次对话。

| 状态 | 含义 |
|---|---|
| 待确认 | 可「确认」或「忽略」 |
| 已执行 | 已写入数据库，卡片从列表移除 |
| 已拒绝 | 点了忽略，不会再执行 |
| 执行失败 | 执行时报错，`error` 字段记录原因 |

已处理的操作不能重复执行，重复请求返回 `conflict`。

## 输出上限与重试

| 设置 | 默认 | 说明 |
|---|---|---|
| 最大重试次数 | `10` | 接口调用失败后的重试次数，范围 0–100，0 表示不重试 |

单次输出上限固定为 `4096`（厂商的 `max_tokens`），不提供设置项。模型回复被截断时
（`stop_reason=max_tokens` / `finish_reason=length`）本轮对话直接结束，不再继续工具调用——
此时工具参数可能不完整，继续执行只会生成脏草稿。已生成的草稿仍会返回，可以确认。

重试只针对临时性失败：限流（429）、超时（408）、5xx、连接失败按指数退避重试（200ms 起，上限 2 秒）；
密钥错误（401）、参数错误（400）会立刻返回。

## 状态流与中止

对话窗的等待提示会实时反映服务端状态：思考中、第 N 次重试及原因、正在执行工具、自动重试后成功。

发送后按钮变成红色方块，点它中止请求：SSE 连接断开，服务端随上下文取消，本轮已生成的草稿会被清理，
刚才的输入退回输入框。

状态流走 `POST /api/ai/chat/stream`，只推过程状态，回复正文一次性返回。

::: tip 反代要关缓冲
前面有 nginx 时确认 `proxy_buffering off;`（或至少对 `/api/ai/chat/stream` 关闭）。
本服务已返回 `X-Accel-Buffering: no`，新版 nginx 会据此自动关闭该路径的缓冲。
:::

## 安全与边界

- AI Key 与草稿内容都加密入库：草稿里可能包含口述的 SMTP 密码。
- 草稿执行走与表单相同的服务层校验，非法数据会在执行时被拒绝。
- 单次对话最多 8 轮工具调用，客户端上传的历史最多 30 条。

::: warning 模型仍可能理解错
确认前看一眼卡片摘要，尤其是删除操作。
:::

## 草稿清理

待确认草稿与已处理草稿都保留 90 天（按创建时间算），每天凌晨 3 点自动清理，没有开关。
清理只删 `ai_actions` 表，不影响真实的提醒与通道。

## 清空对话

浮窗右上角的垃圾桶清空当前对话与本地存储，不撤销已执行的提醒和通道，也不撤销待确认草稿。
