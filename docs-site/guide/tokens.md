# 令牌与外部调用

令牌用于让**程序**调用系统，而不是浏览器。它和面板登录用的 JWT 是两套独立的鉴权机制。

## 与登录的区别

| | 登录令牌（JWT） | API 令牌 |
|---|---|---|
| 用途 | 浏览器访问面板 | 程序调用外部 API |
| 请求头 | `Authorization: Bearer <jwt>` | `X-AUTH: <token>` |
| 有效期 | 72 小时 | 长期，直到被删除或禁用 |
| 范围 | 全部面板接口 | 仅 `/api/external/v1/*` 且只能访问自己创建的提醒 |
| 限流 | 无 | 每令牌 60 次/分钟 |

## 创建令牌

到**令牌**页新建，填写名称并可选设置默认通道。创建成功后明文只在这一次展示，
之后可以在列表里点「查看」再取（明文会保存在数据库里，便于随时取回）。

令牌格式为 `bdrk_` 前缀加一串随机字符，列表里显示前 8 位用于区分。

### 默认通道

外部 API 创建提醒时如果没指定 `channel_ids`，会回退到令牌绑定的默认通道集合。
因此建议创建令牌时就把常用通道选好，之后调用方可以完全不关心通道 ID。

## 权限边界

令牌只能操作**自己创建的**提醒：

- 创建时提醒会被强制打上 `source=api` 和该令牌的 ID
- 查询、修改、删除都会校验归属，访问别人的提醒一律返回「提醒不存在」
- 不能通过外部 API 修改通道，只能读取通道列表

## 限流

每个令牌每分钟最多 60 次请求，超出返回 `429 rate_limited`。限流是进程内计数，
重启服务会重置。

## 使用示例

```bash
curl -X POST http://localhost:8765/api/external/v1/reminders \
  -H "X-AUTH: bdrk_xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "会议提醒",
    "content": "15 分钟后有会议",
    "schedule_type": "once",
    "schedule_spec": { "at": "2026-07-01T14:00:00" }
  }'
```

由于没传 `channel_ids`，这条提醒会发到令牌的默认通道。

## 管理

| 操作 | 说明 |
|---|---|
| 启用 / 禁用 | 禁用的令牌立即失效，调用返回未授权 |
| 修改默认通道 | 只影响之后新建的提醒，已有提醒的绑定不变 |
| 查看明文 | 从数据库取回完整令牌 |
| 删除 | 不可恢复。已由该令牌创建的提醒会保留，但无法再通过 API 访问 |

::: tip 定期检查使用情况
令牌页会显示每个令牌近 24 小时的调用次数，可以据此发现异常或清理不再使用的令牌。
:::

完整的接口说明见[外部 API](/api/external)。
