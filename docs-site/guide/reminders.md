# 提醒与调度

一条提醒由「标题 + 内容 + 调度规则 + 绑定通道」组成。调度规则决定了它什么时候触发。

## 调度规则的两个维度

调度由 **日历** 与 **调度类型** 两个字段共同决定，`schedule_spec` 的字段结构随组合变化：

| 日历 | 支持的调度类型 |
|---|---|
| `solar`（公历） | `once` / `interval` / `cron` |
| `lunar`（农历） | `once` / `interval` |

农历不支持 Cron，因为 Cron 表达式是纯公历语义。

## 公历（solar）

### 单次 · once

指定一个本地时间点，触发一次后不再触发。

```json
{ "at": "2026-07-01T09:00:00" }
```

时间格式为 `YYYY-MM-DDTHH:mm:ss`，按**站点时区**（面板「设置」页配置，默认 `Asia/Shanghai`）解释。
如果这个时间点已经过去，提醒会被保存但不会触发。

### 周期 · interval

从起始时间开始，每隔 `every` 个 `unit` 触发一次。

```json
{ "start_at": "2026-07-01T09:00:00", "every": 1, "unit": "day" }
```

`unit` 可选：`minute`、`hour`、`day`、`month`、`year`。

第一次触发就是 `start_at` 本身。`month` 与 `year` 按日历语义累加，例如 1 月 31 日加一个月会落到 2 月 28/29 日。

### Cron · cron

标准 5 字段 Cron 表达式（分 时 日 月 周）。

```json
{ "expr": "0 9 * * 1-5" }
```

常见写法：

| 表达式 | 含义 |
|---|---|
| `0 9 * * *` | 每天 09:00 |
| `0 9 * * 1-5` | 工作日 09:00 |
| `30 8 1 * *` | 每月 1 日 08:30 |
| `0 */2 * * *` | 每两小时整点 |

## 农历（lunar）

农历调度用 `lunar` / `start_lunar` 描述日期，`hour` 与 `minute` 单独给出时刻。
农历日期会在计算时自动换算成对应的公历时间。

### 单次 · once

```json
{
  "lunar": { "year": 2027, "month": 1, "day": 1 },
  "hour": 9,
  "minute": 0
}
```

### 周期 · interval

```json
{
  "start_lunar": { "year": 2026, "month": 1, "day": 1 },
  "hour": 9,
  "minute": 0,
  "every": 1,
  "unit": "month"
}
```

农历周期的 `unit` 支持 `day`、`month`、`year`：

- `day`：按农历天数往后推
- `month`：按农历月份累加，月份超过 12 自动进位到下一年
- `year`：按农历年份累加

两个隐含策略固定为：

- **闰月跳过**：只产生非闰月的日期，不会因为当年有闰月而重复触发
- **月末顺延**：目标日在当月不存在时（如农历三十遇到小月），顺延到当月最后一天

农历适合「每月初一 / 十五提醒」「每年春节提醒」这类需求。

## 启用与禁用

提醒可以随时启用或禁用：

- 禁用会清空下次触发时间，并从调度器注销
- 重新启用会基于当前时间重新计算下次触发时间
- 如果规则已经不可能再触发（例如单次的 `at` 已经过去），下次触发时间会保持为空，
  提醒虽然显示为启用但不会再触发；这类提醒建议直接删除
- 如果规则本身解析失败（例如 `schedule_spec` 被改坏），重新启用会失败并保持禁用状态

## 预览下次触发

新建或编辑提醒时，可以点「预览」查看接下来的若干次触发时间，用来验证 Cron 写对没有。
预览最多返回 20 次。

## 试发

编辑弹窗里的「测试」按钮会用**当前表单数据**立刻发送一次，走真实通道，但**不写日志**。
适合在保存前确认内容排版与通道配置是否正常。

试发与正式触发共用同一套渲染逻辑，因此占位符、确认链接（试发时不注入）之外的渲染效果是一致的。

## 来源区分

提醒列表按来源过滤，默认只看面板创建的：

| 来源 | 说明 |
|---|---|
| `web` | 在面板里创建 |
| `api` | 通过外部 API 创建（带令牌 ID，只能由该令牌访问） |

## 删除

删除是硬删除：提醒记录、与通道的关联、以及调度器里的注册项一起清理，不可恢复。
列表支持勾选多条后批量删除。
