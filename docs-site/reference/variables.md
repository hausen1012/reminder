# 模板变量

正文、标题与 Webhook 模板里可以写 `{{变量名}}`，发送时替换成实际值。
这里的变量在**一次触发**时构建，同一批变量会用于所有通道。

## 时间类

| 变量 | 示例值 | 说明 |
|---|---|---|
| `{{now}}` | `2026-07-01 09:00:03` | 实际开始投递的时间 |
| `{{now_date}}` | `2026-07-01` | 同上，只有日期 |
| `{{now_time}}` | `09:00:03` | 同上，只有时间 |
| `{{fire_at}}` | `2026-07-01 09:00:00` | 计划触发时间 |
| `{{trigger_at}}` | `2026-07-01 09:00:00` | 与 `fire_at` 相同，兼容旧写法 |
| `{{trigger_date}}` | `2026-07-01` | 计划触发时间，只有日期 |
| `{{trigger_time}}` | `09:00` | 计划触发时间，只有时分 |
| `{{weekday}}` | `周三` | 计划触发时间是星期几 |

::: tip now 与 fire_at 的区别
正常触发时两者几乎相同。但在**兜底补发**场景下，实际投递时间会晚于计划时间，
这时 `{{now}}` 是「真实发送的时刻」，`{{fire_at}}` 是「本该触发的时刻」。
想让文案更准确，用 `{{fire_at}}`。
:::

## 内容类

| 变量 | 说明 |
|---|---|
| `{{title}}` | 提醒标题（可被再次渲染） |
| `{{content}}` | 正文。在 Webhook 模板里拿到的是**已渲染**的正文 |
| `{{lunar_date}}` | 当前日期对应的农历，如 `农历丙午年五月十七` |

## 元信息类

| 变量 | 说明 |
|---|---|
| `{{reminder_id}}` | 提醒 ID |
| `{{reminder_source}}` | 来源，`web` 或 `api` |
| `{{source}}` | 与 `reminder_source` 相同，兼容旧写法 |

## 确认类

| 变量 | 说明 |
|---|---|
| `{{confirm_url}}` | 确认链接。**只有开启「需要确认」的提醒才会注入**，其他情况为空串或原样保留 |

## 通道试发专用

在通知页对单个通道做「测试发送」时，用的是另一套简单变量：

| 变量 | 说明 |
|---|---|
| `{{channel_type}}` | 通道类型，如 `smtp` |
| `{{now}}` | 当前时间 |
| `{{title}}` / `{{content}}` | 测试消息的标题与正文 |

测试消息本身是固定的（「通道试发 - <类型>」），因此这几个变量主要用于确认通道能正确接收。

## 渲染规则

- 只做字符串替换，不支持条件、循环、表达式、函数
- 变量名允许字母、数字、下划线、点号，前后可以有空白
- 未定义的占位符**原样保留**，便于发现拼写错误
- 不做递归展开

::: warning 占位符不能用于自我引用
`{{title}}` 与 `{{content}}` 在渲染时使用的是提醒自身的字段值，
因此把它们写在自己的字段里不会无限展开，而只是得到一次替换后的结果。
:::

## 示例

正文：

```
{{weekday}}提醒（{{now_date}}，{{lunar_date}}）

今天的待办：{{content}}

处理完请点这里确认：{{confirm_url}}
```

Webhook 的 Body 模板：

```json
{
  "msg_type": "text",
  "summary": "{{title}}",
  "detail": "{{content}}",
  "fired_at": "{{fire_at}}",
  "reminder": "{{reminder_id}}"
}
```

获取查询参数模板：

```
text: {{title}} — {{content}}
at: {{fire_at}}
```
