# 常见问题

## 部署与配置

### 忘记密码

能登录就到**设置**页用原密码修改。进不去时可以清空数据库文件重新初始化（会丢数据），
或用 bcrypt 哈希直接改库里的密码：

```go
// backend/hashmain/main.go，运行 go run ./hashmain 得到哈希后删掉该目录
package main

import (
	"fmt"

	"golang.org/x/crypto/bcrypt"
)

func main() {
	h, _ := bcrypt.GenerateFromPassword([]byte("新密码"), bcrypt.DefaultCost)
	fmt.Println(string(h))
}
```

```bash
sqlite3 /path/to/reminder.db \
  "UPDATE users SET password = '<刚生成的哈希>' WHERE username = 'admin';"
```

### 改了 USERNAME / PASSWORD 但没生效

这两个变量只在 `users` 表为空时用于创建第一个账号，之后请到**设置**页改密码。

### 每次重启都要重新登录

`JWT_SECRET` 留空时每次启动随机生成，旧令牌全部失效。显式配一个固定值即可。

### 手机上点确认链接打不开

确认链接用**设置 → 站点地址**拼接（初始值来自 `SITE_URL`）。如果它是 `localhost`，
手机上访问到的是手机自己。改成手机能访问的内网 IP、域名或反代地址即可，改完立即生效。

### 换了 ENCRYPTION_KEY 后通道发送失败

通道敏感字段以密文入库，换密钥后旧密文解不开，到**通知**页把对应字段重填一遍。
另外未配置 `ENCRYPTION_KEY` 时用的是内置固定密钥，安全等级等同明文，生产环境务必显式配置。

### 数据存在哪里，怎么备份

全部在一个 SQLite 文件里（路径见 `DB_PATH`）。备份就是复制这个文件（连同 `-wal`、`-shm`），
或用 `sqlite3 ... ".backup ..."` 在线备份。详见[部署](/guide/deployment)。

## 调度与触发

### 提醒保存了但没有触发

按顺序排查：是否启用、是否绑定至少一个启用的通道、算出的下次触发时间是否在未来、
监控页「已注册数量」里有没有它、服务端日志里有没有「注册到调度器失败」。

### 触发时间比预期晚了

走了兜底补发：主调度器漏掉了这次触发，扫描器在容忍窗口内补发，此时 `{{now}}` 与 `{{fire_at}}` 不同。
如果频繁发生，检查进程重启、机器休眠或系统时间是否被调整过。

### Cron 表达式不生效

只支持标准 5 字段（分 时 日 月 周），不支持秒字段。`0 0 9 * * *`（6 字段）会解析失败。
新建提醒时用「预览」验证。

### 农历日期总是不对

闰月跳过、月末顺延，所以同一农历日期对应的公历日期每年浮动。用「预览」核对接下来几次的实际时间。

### 服务器宕机恢复后收到一堆过期提醒

说明落进了容忍窗口。把 `MISS_TOLERANCE_MINUTES` 调小，超窗口的触发会标记为 `expired` 而不发送。

## 通知与通道

### 邮件发不出去

国内邮箱要用授权码而不是登录密码；465 走 SSL、587 走 STARTTLS；部分服务要求发件人与登录账号一致。

### 钉钉提示签名不匹配

安全设置选了「加签」就必须填密钥；只用「自定义关键词」则密钥留空。两者不能混。

### 部分通道成功、部分失败

正常结果，日志状态为 `partial`，展开日志可以看每个通道的失败原因。

### 试发成功但正式触发失败

试发用的是**当前表单数据**，正式触发用的是**已保存的配置**。检查保存后敏感字段是否被清空过。

## 确认机制

### 确认链接点了没反应

链接已过期（72 小时），或者站点地址配置不对。显示「之前已确认」表示这条链接点过了，
不会重复生效，也不会报错。

## 外部 API

### 调用返回「令牌无效」

请求头是 `X-AUTH`（不是 `Authorization`），值是完整的 `bdrk_...` 明文，且令牌处于启用状态。

### 返回 429

每个令牌每分钟 60 次。计数在进程内存里，重启会清零。

### 查询别人创建的提醒返回 404

令牌只能访问自己创建的提醒，越界一律返回「不存在」，避免泄露其他提醒的存在。

### 更新接口只传了标题，结果调度规则没了

`PUT` 是全量覆盖，`calendar`、`schedule_type`、`schedule_spec` 必须一起传。
