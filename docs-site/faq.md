# 常见问题

## 部署与配置

### 忘记密码了怎么办

如果还能进面板，到**设置**页用原密码修改。

如果进不去，有两种办法：

**办法一：清空重建**（会丢失所有数据）

停服务，删掉 `DB_PATH` 指向的数据库文件，重新启动。系统会按 `USERNAME` / `PASSWORD`
重新创建管理员账号。

**办法二：只重置密码**（保留数据）

在 `backend` 目录下新建一个临时文件 `hashmain/main.go`：

```go
package main

import (
	"fmt"

	"golang.org/x/crypto/bcrypt"
)

func main() {
	h, err := bcrypt.GenerateFromPassword([]byte("新密码"), bcrypt.DefaultCost)
	if err != nil {
		panic(err)
	}
	fmt.Println(string(h))
}
```

运行它拿到哈希：

```bash
cd backend
go run ./hashmain
```

然后用 sqlite3 更新密码（记得删掉临时目录）：

```bash
sqlite3 /path/to/reminder.db \
  "UPDATE users SET password = '<刚生成的哈希>' WHERE username = 'admin';"
```

### 改了 USERNAME / PASSWORD 环境变量但没生效

这两个变量只在 `users` 表为空时用于创建第一个账号。库里已有账号后它们就完全不起作用了，
要改密码请到面板**设置**页操作。

### 每次重启都要重新登录

`JWT_SECRET` 留空时每次启动会随机生成，导致已签发的令牌全部失效。显式配一个固定值即可。

### 手机上点确认链接打不开

确认链接用 `BASE_URL` 拼接。如果 `BASE_URL` 是 `http://localhost:8765`，
手机访问的是它自己的 localhost。改成手机能访问的地址——内网 IP、域名或反向代理地址。

### 换了 ENCRYPTION_KEY 后通道发送失败

通道的敏感字段（SMTP 密码、钉钉密钥、Webhook Authorization）以密文入库，
换密钥后旧密文解不开。到**通知**页把对应字段重新填一遍即可。

同理，没有配置 `ENCRYPTION_KEY` 时用的是编译进二进制的固定密钥，安全性等同于明文，
生产环境请务必显式配置。

### 数据存在哪里，怎么备份

全部在一个 SQLite 文件里，路径由 `DB_PATH` 指定。备份方式是复制这个文件
（连同同目录下的 `-wal`、`-shm`），或者用 `sqlite3 ... ".backup ..."` 做在线备份。
详见[部署](/guide/deployment)。

## 调度与触发

### 提醒保存了但没有触发

按顺序排查：

1. 提醒是否处于**启用**状态
2. 是否绑定了至少一个**启用的**通道
3. 调度规则算出来的下次触发时间是否在未来（单次时间已过就不会触发）
4. 监控页的「已注册数量」里有没有这条提醒
5. 服务端日志里有没有「注册到调度器失败」

### 触发时间比预期晚了

可能走了兜底补发：主调度器漏掉了这次触发，由扫描器在之后的某一轮补发。
这种情况下 `{{now}}` 与 `{{fire_at}}` 会不同。

如果经常发生，检查进程是否频繁重启、机器是否休眠、系统时间是否被调整过。

### Cron 表达式不生效

只支持标准 5 字段（分 时 日 月 周），不支持秒字段。`0 9 * * *` 是每天 9 点，
`0 0 9 * * *`（6 字段）会解析失败。可以在新建提醒时用「预览」验证。

### 农历提醒总是不在预期日期

农历日期换算依赖农历库，闰月与大小月的边界情况容易出错。建议：

- 用「预览」核对接下来几次的实际公历时间
- 农历周期固定跳过闰月、月末顺延，所以每年同一个农历日期对应的公历日期会浮动

### 服务器宕机一段时间后收到一堆过期提醒

说明落进了容忍窗口。把 `MISS_TOLERANCE_MINUTES` 调小，或者接受「过期就不发」的行为——
超出窗口的触发会被标记为 `expired` 而不发送。

## 通知与通道

### 邮件发不出去

常见原因：用登录密码而不是授权码（国内邮箱需要先在设置里开启 SMTP 并生成授权码）、
端口与加密方式不匹配（465 走 SSL，587 走 STARTTLS）、服务器要求发件人地址与登录账号一致。

### 钉钉提示签名不匹配

机器人安全设置里选了「加签」时必须把密钥填进通道配置；如果只是用了「自定义关键词」，
密钥留空即可。两者不能混。

### 部分通道成功、部分失败

这是正常结果，日志状态会显示 `partial`。展开日志能看到每个通道的失败原因。

### 试发成功但正式触发失败

区别在于试发用的是**当前表单数据**、走真实通道但不写日志；正式触发用的是**已保存的配置**。
如果保存后失败而试发成功，检查保存的配置里敏感字段是否被清空过。

## 确认机制

### 确认链接点了没反应

可能的原因：链接已过期（72 小时）、已经被点击过一次（令牌一次性）、
`BASE_URL` 配置不对导致域名指错。

### 为什么重发间隔不能设小于 60 秒

太短的间隔没有实际意义——还没拿起手机消息就重复好几遍。60 秒是设计上的下限。

### 确认之后下一轮还会提醒吗

会。确认只终止**当前这一轮**的重发链，调度规则照常生效，下次到点依然会发出新提醒。

## 外部 API

### 调用返回「令牌无效」

检查请求头名称是 `X-AUTH`（不是 `Authorization`），值是完整的 `bdrk_...` 明文，
并且令牌在面板里处于启用状态。

### 返回 429

每个令牌每分钟 60 次请求，超了就等一会儿。限流计数在进程内存里，重启服务会清零。

### 查询别人创建的提醒返回 404

这是设计如此。令牌只能访问自己创建的提醒，越界访问一律返回「提醒不存在」而非「无权访问」，
避免泄露其他提醒的存在。

### 更新接口只传了标题，结果调度规则没了

`PUT` 是全量覆盖语义，未传的字段会被写成零值。更新时要把 `schedule_spec`、`calendar`、
`schedule_type` 等字段一起传。

## 其他

### 支持多用户吗

不支持。系统按单人 / 单小组自用设计，只有一个管理员账号，所有数据共享。

### 可以部署多个副本做高可用吗

不可以。调度器、限流器、确认链都是进程内状态，SQLite 也不适合多写入方。
单进程是刻意的设计取舍。

### 日志会一直增长吗

默认不会自动清理。可以在日志页手动清理，或者把 `LOG_AUTO_PURGE_DAYS` 设为大于 0，
系统会在每天凌晨 3 点自动清理超过保留期的日志。
